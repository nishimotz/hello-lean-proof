# 来歴: 手計算から Lean まで

このページは補助読み物。「なぜ今 Lean なのか」の背景を知りたい人向け。
演習には出てこないので、読みたい人だけ読んでほしい。

---

## 1. 何を機械に任せてきたか

科学計算の道具史は、**人間が頭で確認していたものを機械に渡してきた**流れとして読める。

```
手計算
  │  計算を機械に
  ▼
Mathematica (1988〜) / SymPy      ← 式変形・積分・求解
  │  数値計算へ分岐
  ▼
NumPy / SciPy                      ← 配列計算・数値アルゴリズム
  │  アルゴリズムの主張を載せる
  ▼
STUMPY (2019)                      ← 時系列データマイニングの実装
  │  主張の真偽を機械で判定
  ▼
Lean / TLA+                        ← 証明
```

**置き換えではない**。SymPy は Mathematica の代替だが、Lean は SymPy の代替ではない。**保証の階層が 1 つ上がった**。

---

## 2. 各段が「何を保証しないか」

道具を選ぶとき、重要なのは「何ができるか」より「**何を保証しないか**」。

| 段 | 機械に渡したもの | 保証しないもの |
|---|---|---|
| 手計算 | （なし） | すべて（人間の注意力のみ） |
| Mathematica / SymPy | 式変形の手続き | 結果の意味、量化を含む主張の真偽 |
| NumPy / SciPy | 数値計算の手続き | 浮動小数点誤差、アルゴリズムの性質 |
| STUMPY | アルゴリズムの実装 | 原典の主張そのもの、すべての入力での正しさ |
| Lean / TLA+ | 主張の真偽の判定 | 仕様の正しさ、モデルと実装の一致 |

### 計算と証明は別の操作

| | 計算 | 証明 |
|---|---|---|
| 何をするか | 値を求める | 主張がすべての場合で成り立つと示す |
| 失敗の形 | 誤った値が出る（気づかなければ通る） | 示せない |
| 例 | `∫ x² dx = x³/3` | `∀x, x + 0 = x` |

SymPy が `x³/3` を返すのは**計算の結果**であり、「すべての x で成り立つ」ことの証明項ではない。Lean が返すのは証明項。

## 3. Lean は万能ではない

このページで一番大事なところ。

| 確かめたいこと | 道具 |
|---|---|
| 「たぶんバグがある」を探す | Hypothesis（ランダムに叩く） |
| 見つかった反例を最小化する | Z3（SMT ソルバ） |
| 式変形が正しいか | SymPy（計算する） |
| 並行・分散の性質 | TLA+（モデル検査） |
| 数学的主張がすべての場合で成り立つか | **Lean**（証明する） |

**Lean が保証しないもの**:

- **仕様そのものの正しさ** — 何を証明すべきかは人間が決める。`fizzbuzz` の定義が正しいかは Lean では分からない
- **モデルと実装の一致** — Lean で示したのはモデルの性質。Python の実装がモデルどおりに動くかは別
- **既存ライブラリの主張** — 誰かが書いたアルゴリズムの正しさは、誰かが証明しない限り保証されない

---

## 4. だからこの教材で学ぶ意味

本教材で扱う「証明＝探索ゲーム」は、この系譜の**最後の段の入口**にすぎない。

だが **「盤面を見て手を選ぶ」** という感覚は、コードベースを見て制約を選ぶ感覚と同じ形をしている。
検証の証拠物を作る側の技術として、最初の 1 歩になる。
